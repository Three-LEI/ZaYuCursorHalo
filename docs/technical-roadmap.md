# CursorHalo 技术路线

> 版本：v0.1（规划稿） · 2026-11-18  
> 目标：先交付一个在 Windows 7 上稳定、低延迟、现代感强的**鼠标跟随高亮**工具；架构为后续按键组合显示留好位置。  
> **硬约束：Windows 7 SP1 x86 是每项新功能的第一个验收目标；未通过 [Win7 兼容门禁](win7-compatibility.md) 的功能不得进入发布。**

---

## 1. 产品与兼容性契约

### 1.1 首版做什么

- 常驻系统托盘，左键快速开关，右键打开极简面板，可进入设置。
- 鼠标周围显示跟随光环；默认 1:1 跟手，不做拖尾、不做全屏压暗。
- 全局快捷键开关，默认 `Ctrl + Alt + H`，可修改。
- 基础设置：光环大小、透明度、颜色、开机启动、快捷键。
- 单实例、配置持久化、自动处理显示器/DPI/睡眠唤醒变化。

### 1.2 首版明确不做

- 不做屏幕采集、录屏注入、驱动或内核组件。
- 不做全屏变暗的聚光灯模式（首版）；它和 Win7 分层窗口的更新成本冲突，后续单独立项验证。
- 不做管理员权限、开机服务、联网、自动更新、遥测。
- 不做键盘记录落盘。

### 1.3 兼容性契约（验收口径）

| 项目 | 契约 |
|---|---|
| 操作系统 | Windows 7 **SP1** x86 / x64；Aero 与经典/基本主题都要可用 |
| 后续系统 | Windows 8.1 / 10 / 11 x64（同一套代码，动态适配） |
| 运行时依赖 | 无 .NET、无 Java、无 Electron、无 Qt、无 WebView2、无 VC++ Redistributable |
| 权限 | 普通用户权限；不安装服务/驱动；不要求管理员 |
| 网络 | 完全离线可用，首版不发起任何网络请求 |
| 交付物 | 绿色版单 exe（另加可选安装器）；x86 为主，x64 同时构建 |
| 输入行为 | 只旁路观察，不拦截、不注入、不改变系统输入 |

**“绝对兼容”按可验证契约执行**：用干净的 Win7 SP1 x86/x64 虚拟机 + 一台真实 Win7 机器做发布门禁，而不只靠“代码看起来兼容”。

## 2. 竞品定位

参考对象 [Cursor Highlight](https://github.com/Hazyzh/cursor-highlight) 是 Electron 17 应用，提供跟随光环、滚轮缩放和画笔。差异点：

| 维度 | 本项目目标 |
|---|---|
| 体积/内存 | 原生单 exe，目标安装体积 < 3 MB、常驻内存 < 20 MB |
| 性能 | 事件驱动，无全屏刷新；按显示合成节拍更新，静止时几乎不占 CPU |
| Win7 | 原生 Win32 子集 + 静态 CRT，不依赖 Chromium/Electron 的 Win7 尾巴 |
| 高 DPI/多屏 | 从第一版纳入坐标与 DPI 抽象，不靠系统缩放糊过去 |
| UI | 自绘极简界面，统一 1.5px 线条图标，不用原生控件的旧观感 |
| 未来 | 键盘组合可视化、点击反馈等共用同一套轻量叠加层基础设施 |

> Electron 22 是最后一个支持 Win7/8/8.1 的版本，且已于 2023 年结束支持。这条路线不适合作为“Win7 绝对兼容”的基础。

## 3. 技术选型

### 3.1 结论

**C++17 + Win32 + COM + Direct2D 1.0 + DirectWrite 1.0**，使用 **MSVC v141 工具集 + 静态 CRT** 构建。

### 3.2 为什么不用这些方案

| 方案 | 不采用的原因 |
|---|---|
| Electron / Tauri + WebView2 | Win7 运行时支持已结束，安装包大、内存高、输入延迟不可控 |
| WinUI 3 / UWP | 不支持 Win7 |
| WPF / .NET Framework 4.8 | 要额外依赖 .NET；透明叠加层最终仍要回到分层窗口，性能与可控性不如原生 |
| Qt | 授权、DLL 体积和 Win7 维护成本；为一个轻量叠加层过重 |
| 原生 + 硬件 D3D 叠加层 | Win7 没有 `WS_EX_NOREDIRECTIONBITMAP`/DirectComposition 这条现代路径；为小区域做 GPU 纹理回读通常得不偿失 |

### 3.3 叠加层技术结论

Win7 上实现“逐像素透明、点击穿透、总在最前”的唯一成熟路径是：

```text
WS_EX_LAYERED 窗口
    + Direct2D 1.0 离屏绘制
    + UpdateLayeredWindow 一次性提交位置与内容
```

首版采用 **D2D 软件光栅**：把预乘 BGRA 表面（WIC bitmap，必要时退回 DIB）画好后，通过 GDI interop 取 DC，交给 `UpdateLayeredWindow`。理由：

- 光环只有一两百像素见方，CPU 软件光栅成本极低；每帧只提交一个小表面。
- 避免 GPU 渲染回读到系统内存再交给 User32 的额外往返，也不需要用户有可用 GPU。
- 虚拟机、远程桌面、老显卡、驱动异常机器上行为一致，特别适合“绝对兼容 Win7”。

设置窗口是普通窗口，用 `ID2D1HwndRenderTarget` 渲染即可；只有叠加层需要软件表面。

> 备选：P0 阶段若软件路径达不到高刷下的帧预算，则改用 D3D10.1 + GDI-compatible 纹理 + D2D 表面渲染，再加同样的 ULW 提交。该路径仅在 P0 数据证明必要时引入，不预先增加复杂度。

## 4. 总体架构

```text
┌──────────────── UI 线程 ────────────────┐
│ WinMain / 单实例                         │
│ 设置窗口（D2D 自绘）                     │
│ 托盘图标 / 托盘面板 / 全局热键 / 配置    │
└───────────────┬─────────────────────────┘
                │ 配置变更、启停命令
┌───────────────▼─────────────────────────┐
│ 叠加层渲染线程                           │
│ 光环 Surface + 未来键盘 Surface          │
│ 帧调度器 / D2D 资源 / ULW 提交           │
└───────────────▲─────────────────────────┘
                │ 唤醒事件、点击/按键记录
┌───────────────┴─────────────────────────┐
│ 独立低级钩子线程                         │
│ WH_MOUSE_LL（首版）                      │
│ WH_KEYBOARD_LL（未来，按需启用）         │
│ 回调只做入队 + SetEvent，< 100 µs        │
└─────────────────────────────────────────┘
```

### 4.1 模块划分

```text
src/
  app/        入口、单实例、生命周期、崩溃兜底
  platform/   窗口、DPI、托盘、热键、开机启动、显示器
  input/      低级鼠标/键盘钩子线程、无锁事件环
  overlay/    叠加窗口、表面、渲染器、帧调度器
  render/     D2D/DWrite 封装、主题、线图标、几何
  ui/         设置窗口、托盘面板、自绘控件
  config/     INI 读写、原子保存、迁移
  core/       高亮状态机、几何与命中测试
tests/        纯逻辑单元测试 + 手工兼容性清单
tools/        性能基准、Win7 导入表检查、截图对比
```

### 4.2 线程原则

- **UI 线程**：消息循环、托盘、设置界面。任何输入回调都不在这里做重活。
- **渲染线程**：独占叠加窗口和 D2D 设备资源；每帧只读最新光标位置，不排队重放历史帧。
- **钩子线程**：调用 `SetWindowsHookEx(WH_MOUSE_LL)` 必须有消息循环；回调内不绘制、不加锁、不写日志、不调用可能阻塞的 API。Windows 7 对低级钩子有 300 ms 回调超时并可能静默摘钩，因此未来键盘钩子独立成线程，避免拖累鼠标高亮。
- 跨线程用“最新值 + 事件”的无锁 SPSC 环，杜绝帧率被锁竞争拉低。

## 5. 跟随高亮的实现细节

### 5.1 叠加窗口

```text
风格：WS_POPUP
扩展：WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW |
      WS_EX_TOPMOST | WS_EX_NOACTIVATE
行为：WM_NCHITTEST -> HTTRANSPARENT
显示：ShowWindow(SW_SHOWNOACTIVATE)，永不 SetForegroundWindow
```

必须满足：

- 不出现在任务栏和 Alt+Tab；鼠标点击穿透；不抢焦点。
- 窗口尺寸只包住当前光环和光晕的最大范围（默认约 110×110，125% DPI 下 138×138；随用户半径缩放，通常不超过 320×320），**绝不做全屏透明窗口**。
- **光环内容只在尺寸、DPI、样式或动效变化时绘制**，`UpdateLayeredWindow` 提交一次。
- 纯跟随阶段把缓存好的分层窗口用 `SetWindowPos` 整像素移动；P0 实测这比每帧重绘 + ULW 明显省 CPU。若某个平台移动分层窗口有问题，回退为每次 ULW 位置+内容。
- 任务栏是 shell 保留层，普通应用不能可靠覆盖；P0 在显示时把叠加层插到 `Shell_TrayWnd` 之后，让它从第一帧起就在任务栏下方，避免启动后“先浮上去、点击又掉下来”的跳变。
- 位置跟随使用 `GetCursorPos()` 的整像素屏幕坐标；默认不做弹性/拖尾插值，先保证“贴手”。

### 5.2 视觉参数（首版默认）

- 光环半径 36 px（96 DPI 下），可调 24–96 px。
- 2 px 主描边 + 低透明度外光晕 + 深色边缘 + 内高光，兼顾亮/暗背景。
- 默认强调色 `#5B8DFF`，可在预设色和自定义色中切换。
- 默认不透明度 90%；光环中心透明，不遮挡指针本体。
- 不用模糊/阴影贴图堆叠：D2D 1.0 的效果能力有限，且会增加每帧成本；用径向渐变和双色描边实现干净的“光晕”。

### 5.3 渲染循环

```text
等待：鼠标移动事件 / 动效截止时间 / 显示器变化 / 退出
  ↓
读取最新 GetCursorPos()
  ↓
内容是否需要变化？
  ├─ 否：SetWindowPos 移动缓存窗口（不重绘）
  │     等待下一次 DWM 合成节拍
  └─ 是：D2D 绘制小表面
         UpdateLayeredWindow（新内容 + 位置）
         等待下一次 DWM 合成节拍
```

核心策略：

- **不固定 Sleep(16)**。先读 DWM 合成周期，再按节拍提交。
- 有 DWM 合成时优先用 `DwmFlush` 做节拍对齐；同时读取 `DWM_TIMING_INFO.qpcRefreshPeriod` 做统计和兜底。
- P0 实测：165 Hz 下 `DwmFlush` p50 等待 5.70 ms，帧间 p99 6.49 ms；纯定时器模式 CPU 是 DWM 模式的 3.7 倍，因此默认固定为 DWM 节拍。`DwmIsCompositionEnabled` 关闭时才退回定时器。
- 纯跟随阶段缓存光环，只移动窗口；帧内只取最新光标，不补画中间帧。空闲 350 ms 后停止帧循环，只留静态画面。
- 保持 UI 线程和渲染线程分离；设置窗口打开时也不影响光环跟手。
- 未来点击波纹/拖尾等需要动态内容的效果，只在动画期间重新绘制，回到静态跟随后退回缓存移动路径。

### 5.4 高帧率的真实边界

- Win7 Aero 的实际上限取决于 DWM 合成刷新率；本工具目标不是“数字上写 240 FPS”，而是在 60/120/144 Hz 下**不掉帧、不抖、不积延迟**。
- Win7 关闭 Aero 时走定时器路径，以实测刷新率为上限；不会为了数字强行空转。
- 高刷屏上的表现必须在真实 Win7 硬件上验证，虚拟机 60 Hz 不能替代。
- 目标是输入到提交 p95 < 1 个刷新周期，视觉延迟通常再加 1–2 个合成周期；这一项用 QPC 统计，必要时再上高速相机复核。

### 5.5 空闲与能耗

- 静止时不渲染、不轮询 DWM、不占用定时器。
- 不使用全局 `timeBeginPeriod(1)` 常驻；只在确实需要的帧调度阶段短暂提升，并立即恢复。
- 移动结束 300 ms 后退出节拍循环。
- 关闭高亮时销毁/隐藏叠加窗口并停掉钩子，内存与 CPU 回到托盘级。

## 6. 托盘与界面

### 6.1 托盘交互

- 左键单击：立即开关高亮，图标切换“亮/暗”状态。
- 右键：打开紧凑自绘面板（约 264 px 宽）：
  - 状态行：`高亮已开启`
  - 主开关
  - `打开设置…`
  - `退出`
- 首次运行只自动展开一次托盘面板（P4 改版后不再显示底部溢出提示），不弹模态窗口；完成后写 `first_run=0`。
- Explorer 重启后监听 `TaskbarCreated` 自动恢复图标；睡眠唤醒、分辨率变化后自愈。
- 托盘图标必须为多尺寸 `.ico`（16/20/24/32/48），用线条光环图形，16 px 下简化细节。

> 不采用又长又挤的原生右键菜单作为主界面；它只用于极端兼容性兜底。

### 6.2 设置窗口布局

默认 600×560（逻辑像素），固定尺寸、无最大化；左侧 156 px 导航，右侧一次只显示一个页面，空气感优先。高亮页预览按 1:1 实际尺寸绘制。

```text
┌──────────────────────────────────────────────┐
│  CursorHalo                            —  ×  │
│                                              │
│   ◯  高亮       鼠标高亮                     │
│   ◯  外观       让指针始终清晰可见           │
│   ◯  通用                                    │
│                  ┌────────────────────────┐  │
│                  │          ◎             │  │
│                  │       实时光环预览      │  │
│                  └────────────────────────┘  │
│                                              │
│                  大小       ───────●──  44    │
│                  不透明度   ─────●────  90%   │
│                                              │
│                  颜色       ●  ●  ●  ●  +     │
│                                              │
│                  开机启动                 ○──│
└──────────────────────────────────────────────┘
```

- 首版只有“高亮 / 外观 / 通用”三页；“按键”等未来功能完成后再出现在导航中，不放灰色占位。
- 每页最多 3–4 个设置组，组间距 24 px，内容不堆叠。
- 设置项即时生效；窗口关闭即隐藏，不退出进程。

### 6.3 视觉规范

| 项目 | 规范 |
|---|---|
| 线条图标 | 1.5 px 描边、圆角端点、20×20 视觉框；全部用 D2D 几何自绘 |
| 字体 | `Segoe UI` + 中文回退 `Microsoft YaHei`；标题 18 px，正文 13 px，辅助 12 px |
| 间距 | 8 px 网格；页面内边距 32 px；控件垂直间距 20 px |
| 圆角 | 控件 8 px，面板 12 px；Win7 窗口本身不做圆角（避免额外分层窗口成本） |
| 主题 | 浅色/深色，默认跟随系统；Win7 无系统深色设置时用浅色，可手动切换 |
| 浅色 | 背景 `#F6F7F9`、文字 `#17181A`、次要 `#6E727A`、强调 `#4F7CFF` |
| 深色 | 背景 `#17181B`、文字 `#F0F1F3`、次要 `#A2A7B0`、强调使用当前光环色 |
| 动效 | 120–180 ms ease-out；控制面板不做过场动画；尊重系统“减少动画”设置 |
| 禁止 | 彩色填充图标、Emoji 图标、渐变按钮、拥挤的胶囊标签、无意义分隔线 |

### 6.4 窗口实现

- 使用自绘非客户区：顶部可拖拽，右上角为线条关闭/最小化图标；固定尺寸。
- Aero 开启时用 `DwmExtendFrameIntoClientArea` 取得系统阴影；Aero 关闭时画 1 px 边界。
- D2D HWND 渲染目标 + DirectWrite；处理 `D2DERR_RECREATE_TARGET` 与显卡驱动重置。
- 首版控件集：开关、滑杆、色块、分段选择、按钮、滚动? 不需要滚动，页面固定高度。
- 键盘操作：设置/调色盘/托盘面板的 Tab 焦点、焦点环、方向键调整、Enter/Space 激活和 Esc 关闭已跑通；高对比度与 UIA 暴露仍待补。
- 自绘控件不阻塞 IME 输入；首版没有文本输入，后续快捷键录制单独处理。

### 6.5 快捷键

- 默认 `Ctrl + Alt + H` 开关高亮；用 `RegisterHotKey` 实现，不为此常驻低级键盘钩子。
- 注册冲突时明确提示并允许重设；不抢占 `Esc`、不劫持滚轮。
- 快捷键录制在录制期间临时安装 `WH_KEYBOARD_LL`，以便捕获已被其他程序注册的组合并做冲突检测；录制结束/取消/失焦立即卸载，不做常驻全局键盘监听。

## 7. 配置、启动与单实例

- 配置格式：UTF-8 INI，人类可读、易排障；路径 `%APPDATA%\CursorHalo\config.ini`。
- 便携模式：exe 同目录存在 `portable.flag` 时，配置写 exe 同级 `config.ini`；写入失败则回退 AppData 并提示。
- 保存策略：写临时文件 → flush → `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)` 原子替换；退出、设置变更、系统关机时保存。
- 配置带 schema 版本；旧版本自动迁移，坏配置回退默认值并保留 `.bak`。
- 开机启动：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不写 HKLM、不需要管理员。
- 单实例：命名互斥体 + 隐藏消息窗口；第二次启动用 `PostMessage` 唤起设置后退出，绝不启动第二个光环。
- 首版无自动更新、无网络、无遥测；崩溃日志默认关闭，可在设置中手动导出诊断信息。

## 8. Win7 兼容性工程

### 8.1 当前开发环境的重要事实

当前机器是 Windows 11。**VS 2022 Build Tools 17.14.45 + MSVC v141 14.16.27023 + Windows SDK 10.0.19041 已安装并验证**：

- Build Tools / v141：`F:\DevTools\VS2022\BuildTools`
- Windows SDK 19041：`D:\Windows Kits\10`（与已有 26100 共存；SDK 安装器不允许第二个根目录，详见 [工具链记录](toolchain-setup.md)）
- 实际构建产物为 PE 6.01、静态 CRT、无 Win8+ 导入，x86/x64 均可编译运行。

原有的 **Visual Studio 2026** 仍保留，但 Microsoft 已明确：**Visual Studio 2026 18.0 起不再支持以 Windows 7/8/8.1 为目标平台**。因此发布构建必须显式使用 v141，不能拿 VS 2026 的默认 v143 产物作为 Win7 发布版。

### 8.2 固定构建链

| 项 | 选择 |
|---|---|
| 编译器 | MSVC v141（14.16，VS 2017 工具集），C++17 |
| IDE/构建工具 | VS 2022 Build Tools 17.x 与现有 VS 2026 并存安装 |
| Windows SDK | 10.0.19041（仅用头文件/导入库，目标 API 版本设为 Win7） |
| 构建系统 | CMake + MSBuild/Ninja，固定 Release 参数 |
| CRT | `/MT` 静态链接，确保干净 Win7 无 VC++ Redist 也能运行 |
| 目标宏 | `WINVER=0x0601`、`_WIN32_WINNT=0x0601`、`NTDDI_VERSION=0x06010000` |
| 子系统 | `/SUBSYSTEM:WINDOWS,6.01` |
| 架构 | x86 为主，x64 同源构建；x86 同时覆盖 32/64 位 Win7 |
| 安全链接 | `/DYNAMICBASE /NXCOMPAT`；不依赖仅在 Win8+ 生效的 CFG 机制 |
| 依赖 | 仅 Windows 自带 DLL：user32、gdi32、dwmapi、d2d1、dwrite、windowscodecs、shell32、shlwapi 等 |

不引入 ATL（用 SDK 自带 WRL `ComPtr`）、不引入第三方 UI 库、不使用 `std::filesystem` 这类容易偷偷引入新 API 的组件。

### 8.3 API 纪律

- 只静态链接 Win7 已存在的 API；新 API 一律 `GetProcAddress` 动态探测，失败即走降级路径。
- 禁止使用：`GetDpiForWindow`、`SetProcessDpiAwarenessContext`、`WS_EX_NOREDIRECTIONBITMAP`、DirectComposition、D2D 1.1 接口、`GetSystemTimePreciseAsFileTime`、Win10 通知 API。
- DPI 用 manifest：同时写 Win7 识别的 `dpiAware=true` 与 Win10 的 `PerMonitorV2`；Win7 自动忽略后者。代码里保留系统 DPI 回退路径。
- 所有窗口、字符串使用 Unicode（`W` API）；代码页问题不进入产品。
- 用 `WRL::ComPtr` 管理 COM；渲染线程独立初始化 COM，D2D 工厂逐线程创建。
- DwmApi 用 Win7 存在的 `DwmIsCompositionEnabled` / `DwmFlush` / `DwmGetCompositionTimingInfo`；`DwmGetCompositionTimingInfo` 的 hwnd 参数在 Win7 与 Win8.1+ 不同，需运行时兼容。

### 8.4 发布前兼容门禁

1. `dumpbin /imports` 检查：无缺失 DLL、无 Win8+ 专有导入、无 UCRT/API set 依赖。
2. 干净 Win7 SP1 x86 虚拟机（未装 .NET/VC++ Redist）：启动、托盘、光环、设置、快捷键、退出全通过。
3. 干净 Win7 SP1 x64 虚拟机：同上，并加 x64 构建冒烟。
4. Win7 Aero 与 Basic/Classic 两种主题：渲染、合成节拍、透明与点击穿透都正常。
5. 真实 Win7 机器：至少 1 台，验证 GPU 驱动、60/120/144 Hz 实际观感。
6. Explorer 重启、睡眠/唤醒、锁屏/解锁、切换用户、RDP、显示器拔插。
7. 多屏：主副屏、负坐标、不同分辨率、任务栏在四边。
8. DPI：96/120/144/192（Win7 系统 DPI）；现代系统加混合 DPI 屏。
9. 30 分钟连续移动 + 24 小时常驻（内存无持续增长）。
10. 不装任何额外运行库即可运行；卸载后无残留进程/自启项（安装器路径）。

### 8.5 已知系统限制（不承诺突破）

- UAC 安全桌面、登录界面、锁屏界面不显示叠加层（需要服务/驱动，违背本项目的轻量安全模型）。
- 独占全屏 D3D 游戏通常无法覆盖；无边框全屏游戏视 DWM 行为而定。
- 受保护视频/DRM 画面可能覆盖普通置顶窗口，这是系统设计。
- Win7 本身不支持逐屏独立 DPI；混合 DPI 只能按系统 DPI 处理。
- 部分反作弊/安全软件会拦截全局钩子；提供暂停/兼容模式，但不做注入绕过。

## 9. 性能目标与测法

以下为**目标值**，P0/P1 后按实测修订，不作为发布前的既成结论。

| 指标 | 目标 |
|---|---|
| 启动 | 双击到托盘就绪 < 800 ms（Win7 机械盘放宽到 1.5 s） |
| 体积 | 单 exe < 3 MB |
| 常驻内存 | 空闲 < 20 MB；高亮中 < 30 MB |
| 空闲 CPU | 约 0%（无帧循环、无轮询） |
| 移动 CPU | 165 Hz 跟随实测 4.93% 单核（20 逻辑处理器，约 0.25% 整机）；60 Hz 目标 < 3% 单核；老 Win7 参考机 < 5% |
| 帧节拍 | p99 ≤ 1.25 × 刷新周期；P0 实测 6.493 / 6.060 ms（≈1.07×） |
| 输入到提交 | p95 ≤ 1 个刷新周期；不出现随时间累积的延迟 |
| 长稳 | 30 分钟连续跟手无泄漏；24 小时常驻正常 |
| DPI/多屏 | 任意位置、任意 DPI 下光环中心不偏移 |

测量方式：

- 内置诊断模式：记录每帧 QPC 时间、内容绘制耗时、窗口移动耗时、提交间隔、当前刷新率、掉帧估计。
- 合成节拍以 `DWM_TIMING_INFO` 为参考，不用“定时器设了 16 ms 就算 60 FPS”。
- 测试工具用 `SendInput` 生成 500–1000 Hz 光标轨迹，另做真实鼠标人工测试。
- 最终视觉延迟如需严格证明，用 240 fps 相机拍摄光标与屏幕响应；不作为首版阻塞项。
- 性能数据同时记录在 Win7 VM（含软件渲染/远程桌面场景）和真机，虚拟机数据不作为唯一结论。

## 11. 未来功能：按键组合显示的技术预案

这部分先定架构，等 P1 稳定后再实现。

- **捕获**：独立线程安装 `WH_KEYBOARD_LL`，回调仅读取 `KBDLLHOOKSTRUCT` 并入无锁环；绝不阻塞、不写盘、不注入。Win7 下级联钩子超时会导致系统摘钩，需在睡眠唤醒/长时间停顿后检测并重装。
- **显示内容**：只显示按键名称/组合，不还原输入文本。首版不使用 `ToUnicodeEx` 做字符翻译，避免它改变 Win7 内核键盘缓冲、影响死键和 Alt+Numpad；英文/数字直接映射，其他键用扫描码 + `GetKeyNameTextW` 得到本地化名称。
- **组合规则**：按 `Ctrl / Win / Alt / Shift` 固定顺序排列；同一组合只显示一次；1.5 s 后淡出；纯修饰键长按超过 400 ms 才单独显示；自动忽略按键自动重复和注入事件（可配置）。
- **渲染**：复用同一个分层表面基础设施，但它是独立的小窗口，按事件更新，静止时零重绘。不与光环线程共享可变 UI 状态。
- **隐私**：功能默认关闭；开启时明确说明“仅内存中识别按键名称、不记录字符、不联网”。提供全局暂停开关和按进程排除清单。
- **兼容**：不要求管理员；UAC 安全桌面/登录界面看不到，这是系统边界。

## 12. 主要风险与应对

| 风险 | 概率/影响 | 应对 |
|---|---|---|
| Win7 高刷下 `DwmFlush` 与 ULW 节拍不理想 | 中/高 | P0 实测；帧调度器可替换；退回 waitable timer 或自适应到稳定刷新 |
| 老 Win7 机器软件光栅 CPU 偏高 | 中/中 | 小表面、脏区范围、按需降帧（仍保持跟手）；必要时启用 D3D10.1 备份路径 |
| 没有真实 Win7 测试环境 | 高/高 | 必须准备 Win7 SP1 x86/x64 VM + 真机；未测试不宣称绝对兼容 |
| 低级钩子被安全软件拦截 | 中/中 | 回调极短、单独线程、可见暂停、无注入；文档说明 |
| 自绘 UI 可访问性/输入法细节多 | 中/中 | 首版无文本输入；加键盘导航与高对比度；后续补 UIA |
| 用户机器混合 DPI/多屏 | 中/中 | 第一版 DPI 抽象；Win7 走系统 DPI；现代系统逐屏验证 |
| 签名/安装器在旧 Win7 上的信任问题 | 中/低 | 优先绿色包；如需签名，使用 SHA-256 + 时间戳并实测未打补丁系统；不以管理员安装为必需 |
